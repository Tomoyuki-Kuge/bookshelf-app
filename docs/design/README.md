# 設計書の読み方

最終整理日: 2026-11-26

## 開発環境

2026-11-21のユーザー指定により、PHP 8.5系・Laravel 10.x・MySQL 8.4系に統一する。PHPはSailの8.5ランタイムを使い、ComposerのPHP要件は`8.5.*`、依存解決の基準は`8.5.0`とする。Laravelは既存の10.xを維持し、MySQLの物理条件は[data.md](data.md)に従う。

Laravel 10の[公式対応PHPバージョン](https://laravel.com/docs/10.x/releases#support-policy)は8.1〜8.3であり、PHP 8.5は公式対応範囲外。指定の組み合わせは既存の自動テストで動作を確認し、依存ライブラリ由来の非推奨通知が残る場合は検証結果に記録する。

環境の再構築・検証手順は[プロジェクトのREADME](../../README.md)を参照する。`.env`を読み書きせず検証できるよう、テスト専用設定を`.env.testing`に分離する。テスト対象はMySQL 8.4の`testing`データベースに限定し、既存データを破棄しない。

## 共通方針

- 対象は**基本要件のみ**。完成済みBladeと `docs/reference/` の控えは変更しない。設計書はバックエンドの実装完了を示さない。
- QA・ユーザーの確定回答を要件シートの未反映箇所より優先する。未回答の想定案・文言例・JSON例は、回答が記録されるまで**未確定**。
- 2026-11-22に確認した最新版QAのQ-18・22〜26とQ-19の確定範囲を関連設計へ反映した。ログインの入力エラーも登録画面と統一することを同日のユーザー回答で承認。未指定の個別文言は保留を維持し、認証の上限・重複等は従来の暫定採用を継続する。回答元と履歴はquestions.mdに集約し、更新していない参照資料の控えと区別する。
- Q番号と回答状態は [questions.md](questions.md)、各分野の詳細は下表の文書を参照する。同じ説明・履歴は繰り返さず、変更時は参照先を先に更新する。
- 新たに定義・更新する確認項目で、未確定仕様や資料に記載のない期待結果は「（※仕様保留中）」と明記し、合否を決めない。確定している条件まで保留扱いにはしない。
- S番号は [features.mdの参照資料](features.md#参照資料) に対応する。「行」はシート左端の番号。QAの日付は回答日ではなく確認・反映日。

## 定義の正本と参照

2026-11-26ユーザー承認の設計書整理により、同じ契約の詳細は上表の担当文書へ集約する。questions.mdは回答状態・根拠・承認経緯と未承認案を保持し、確定済みの詳細定義は担当文書へリンクする。担当文書からも対応Q・承認記録を参照する。

- DBの物理型・NULL・索引・外部キーはdata.md、Web入力条件・正式文言・表示先はscreens.md、APIのJSON型・必須条件・応答形式と確定文言はpermissions-api.mdを正本とする。DBの保存容量と入力上限、DB型とJSON型は別の契約として扱う。
- 認可の条件はpermissions-api.md、判定順序・保存単位・排他・例外分類はbehavior.mdへ集約する。画面の閲覧・操作表示や経路表の利用条件は、参照時に必要な要約として残す。
- 暫定文言・未採用の推奨案・正式確認待ちはquestions.mdに保持し、参照先へ移したことを理由に承認状態を変えない。Issue補足の承認日・対象Issue、過去段階の検証範囲を維持し、現在の完了状況とは区別する。
- AC・Tは検証のために必要な操作・期待結果・境界値を残し、仕様全文の再掲や共通の検証手順のみ参照化する。見出しを変更する場合は参照元のリンクも更新する。

## 記載量と更新

画面項目は代表画面と差分、シーケンスは代表1本、受け入れ条件はIssueごとに2〜4行、テストは観点のみ。受け入れ条件はacceptance.md、テストユーザーの役割・データ準備・詳細なテスト観点はtest_case.mdへ分け、同じ12実装単位の順序・番号で対応させる。ACの連番は01からの2桁（例：AC-3-01）とする。Seederの責務・投入仕様はfeatures.mdを正本とし、手動で見える結果とDB内部の検証を分ける。図はMarkdown内のMermaidを使い、クラス図はLaravelのMVCに従うため省略する。仕様変更・応用追加は、先に設計へ反映してから実装・Issue化する。

2026-11-17に設計書・参照仕様書・QA・UI画像と `resources/` を照合した。主要仕様の新たな重大矛盾はなく、残件は [確認先一覧](questions.md#未確定事項の確認先一覧) に集約。資料のUNIQUE記載不足は [data.md](data.md#参照資料からの反映修正)、QAの画像説明誤りは [screens.md](screens.md#根拠と照合結果) に補足する。
