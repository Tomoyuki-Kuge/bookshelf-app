# 機能一覧・今回作らないもの

作成日: 2026-11-14 / QA反映日: 2026-11-14 / 資料更新反映日: 2026-11-15

## 対象範囲と読み方

- **今回は基本要件のみ**。前回のユーザー回答「基本要件のみを対象にする」を引き継ぐ。★応用は今回の対象外。
- 機能一覧はこれから実装する対象であり、実装済みの判定ではない。Bladeは画面の根拠として読み、サーバー側の処理や認可の実装済み根拠にはしない。
- S2等の略称は末尾の参照資料に対応する。「行」はHTMLの行番号ではなく、シート左端の行番号。
- [QA](../reference/bookshelf-spec/qa.html) の回答を [questions.md](questions.md) に反映した。Q-01〜Q-17は回答済み、更新APIの登録者変更可否（Q-18）と画面のエラー文言・表示先（Q-19）は後日確認。DBのCASCADE採用はQ-20、referenceの物理定義反映とジャンル側RESTRICTはQ-21でユーザー決定済み。QAの回答日・回答者名は資料にないため、日付は確認・反映日とする。
- 要件シートとQAに差がある箇所は、QAで合意した仕様を明記する。資料の控えは [参照資料一覧](../reference/bookshelf-spec/README.md) に保存し、提供HTMLやBladeの修正とは区別する。資料内の実装・提出手順を今回の実行指示として扱わない。

### 共通条件と初期データ

入力検証はS8指定の処理をFormRequestに分離し、各FormRequestの `messages()` で日本語を定義する。Q-01〜07の回答により次を確定した。

- 入力不正時は、パスワード以外の入力・ジャンル選択を保持して元のフォームへ戻る。Webの本人以外の編集・更新・削除は403、対象なしは404とする。
- タイトル・著者は各255文字以内。ISBNは必須・ハイフンなし半角数字13桁・一意、出版日は必須で未来日も許可。説明は任意・5,000文字以内、画像URLは任意・255文字以内かつHTTP／HTTPS。その他の確定ルールは [Q-04](questions.md#q-04バリデーションルールの設計シート2-行19) を参照。
- 成功・失敗のフラッシュ文言はQ-02、項目別エラーと認証失敗の文言はQ-05に従う。お気に入り・いいねは追加／解除後のリダイレクトのみでフラッシュ不要。
- 書籍の項目名は `user_id`・`published_date`・`image_url`、いいねは `review_likes` とユーザー／レビューの一意制約を使用する。レビューには投稿者／書籍の一意制約を設けない（Q-08・11）。
- 書籍・レビューの物理削除に伴う関連行の自動削除は、DBの外部キー制約 `ON DELETE CASCADE` を使う（Q-20）。ジャンル側の外部キーは `ON DELETE RESTRICT` とし、DBでも紐付きジャンルの削除を拒否する（Q-21）。採用理由・注意点は [questions.md](questions.md)、referenceを含む物理定義・削除動作・CRUDは [data.md](data.md) を参照。書籍削除時もジャンル本体は残す。

| 初期データ | 基本で指定された内容 |
|---|---|
| ユーザー | 指定の5人。メールをキーに `firstOrCreate`。パスワードは指定値 `password` を `Hash::make()` でハッシュ化する。 |
| ジャンル | 指定の10種類を名前で `firstOrCreate`。小説・ビジネス・技術書・自己啓発・エッセイ・歴史・科学・芸術・料理・旅行。 |
| 書籍 | S9指定の11冊・著者・ISBN・出版日・ジャンルを使用する。作成者は `User::first()`（山田太郎を想定）。説明と指定形式の画像URLも設定。ISBNで `firstOrCreate`、ジャンルは `sync()`。 |
| レビュー | 初回投入は合計32件、各書籍に2〜4件、評価3〜5、具体的コメントを設定し `create()`。実際の投稿機能の評価範囲は1〜5であり、初期データの範囲とは異なる。 |
| お気に入り | 各ユーザーに3〜5冊。`syncWithoutDetaching()`。 |
| いいね | 各レビューに0〜3人、自分のレビューを除く。`syncWithoutDetaching()`。これはシードデータの条件であり、通常操作では自分のレビューにもいいねできる（QA Q-09）。 |
| 実行順 | User → Genre → Book → Review → Favorite → ReviewLike。`DatabaseSeeder` から呼び出し、`sail artisan db:seed` で投入する。QA Q-13により、ReviewSeeder再実行の追加対応は不要。 |

## 今回作らないもの

基本要件のみという回答に基づく対象外を、基本機能との境界とともに示す。

| 対象外 | 根拠・基本との境界 |
|---|---|
| Web一覧のキーワード検索・ジャンルフィルタ・並び順選択・検索条件のページ引き継ぎ | S5 行19、S7 行16–19。通常の最新順・10件表示と、APIの検索・絞り込みは対象に含む。 |
| ISBN検索・Google Books APIによるフォーム自動入力 | S5 行20、S7 行30。ISBNの手入力と検証は基本。 |
| マイ読書レポート | S5 PG14、S7 行48。個人統計は対象外。全体の評価ランキングは基本。 |
| SanctumによるAPIトークン認証・書き込みAPIの所有者認可 | S2 行23、S7 行55、S13 AP06。APIの登録・更新・削除そのものは基本に含む。 |
| 読書計画の一覧・作成・編集・削除・読了操作・状態絞り込み | S2 行24、S5 PG15〜17、S7 行56–65。 |
| 通知一覧・既読化・リマインダー発火・日次バッチによる状態変更 | S2 行24、S5 PG18、S7 行66–68。 |
| 応用用のシード変更と必須項目の任意化 | S8 行17–19、S9 行11–13、S11 行14–16。基本の出版日などの必須条件を応用UIに合わせて緩めない。 |
| CSV機能 | S6 行183の応用画面見出しにのみ「CSV追加」がある。今回は応用全体が対象外。将来実装する際は、S5・S7にない入出力の仕様から確認する。 |
| 二要素認証 | S12 行15に基本・応用とも不要と明記。 |
| パスワード再設定・メール認証フロー、管理者区分 | QA Q-17・03で今回の追加なしを確認済み。標準の認証補助データと利用者向け機能を区別する。 |

パスワード再設定・メール認証の利用者向け画面／メール送信フローは今回追加しない（QA Q-17）。認証補助テーブルはLaravel標準を使用する。管理者区分も設けない（QA Q-03）。

## 更新資料・Bladeとの照合結果

- S5 PG01〜PG13の13画面と共通フォーム・ナビゲーションを照合した。レビュー投稿・お気に入り登録の独立ページは増やさず、認証画面はS7と現Bladeを維持する方針で回答済み（QA Q-16）。
- 2026-11-15更新のS12では、書籍の `user_id`（行24）、`published_date`・`image_url`（行28〜29）、`review_likes`（行56）、ユーザー／レビューの組の一意制約（行58〜59）が確定仕様と一致している。単一 `books.genre_id` は削除され、中間テーブルによる多対多の関係とも一致する。
- ISBNは `varchar(13)`（行27）、書籍の `updated_at` はtimestamp（行32）、レビューコメントはNOT NULL（行38）へ更新済み。型名の誤記も解消した。ジャンル側の `restrictOnDelete()`（行52）はQ-21と一致する。`data.md` の物理定義・未確定事項を更新した。
- 現在のレビュー投稿・編集Bladeはコメントに必須表示がないが、QA Q-04により必須とする。設計書への反映であり、Bladeや保存処理を修正済みとは扱わない。
- 更新APIの `user_id` は必須と確定したが、登録者を変更できるかはQ-18で保留。2026-11-14にユーザーから後日確認の指定があった。
